## 1. Principles

| Principle | What it means in practice |
| --- | --- |
| **Quiet surfaces, loud numbers** | Chrome is white/near-white with 1px rings instead of heavy borders. The money figures (24px mono) are the only large type on the page. |
| **Rings, not borders** | Controls and cards are outlined with a `0 0 0 1px` box-shadow ring plus a soft 1–2px drop. Rings don't affect layout, so a 30px button is really 30px. |
| **Inside strokes** | Figma strokes are *inside*. Structural separators (sidebar edge, header bottom, profile top) are drawn as inset shadows so element sizes match Figma exactly. |
| **One accent** | Brand blue `#1067FF` marks *where you are* (active nav, active month, avatar initials) and *income*. Nothing else is blue. |
| **Buttons don't bounce** | No scale/translate on press. Feedback is a fast colour + shadow change. |
| **Motion is functional** | Every animation answers "why?" — and anything triggered by the keyboard or used dozens of times a day doesn't animate. |

## 2. Token architecture

```
Primitives  --sn-neutral-500, --sn-blue-500 …        raw values, never used in components
   ↓
Semantic    --fg-muted, --bg-sunken, --ring-card …   what components use; re-mapped for dark mode
   ↓
shadcn map  --background, --primary, --border …     so every shadcn/ui primitive inherits the theme
   ↓
Tailwind    text-fg-muted, bg-sunken, shadow-card …  generated by @theme inline
```

Rules:

- Components consume **semantic** tokens only (`text-fg-muted`, never `text-[#757575]` or `--sn-neutral-500`).
- Changing a theme = re-mapping semantic tokens. Primitives never change.
- Type sizes reuse Tailwind's names (`text-sm` etc.) on purpose: `tailwind-merge` only understands built-in size names, so custom names (e.g. `text-body`) get silently dropped when merged with a colour class.

### 3.3 Colour rules

- Text on white must be `fg-muted` or darker for body copy (`#757575` = 4.6:1 on white). `fg-subtle` (`#999`) is only for column headers and timestamps, never for content.
- **Money sign colour:** incoming amounts use `text-positive` with a `+`. Outgoing amounts stay `text-fg` with a true minus `−` (U+2212) — red is reserved for *bad trend*, not for every expense.
- **Trend sentiment ≠ direction.** "Expenses +4.7%" is an *up* arrow coloured *negative*. Model both (`trend`, `sentiment` in `lib/data.ts`).

### 5.2 Breakpoints

Tailwind defaults. The Figma frame is the `xl` layout; everything below is a designed extension.

| Name | Min width | What changes |
| --- | --- | --- |
| base | 0 | Phone: 16px page padding, 12px gaps, KPI 2 × 2 at 20px figures, compact chart axes, docked chart readout, list instead of table |
| `sm` | 640px | 16px gaps, 24px KPI figures, full axis labels, "Download" label |
| `md` | 768px | 24px page padding, inline search + Help, floating chart tooltip, table, two-month date picker |
| `lg` | 1024px | Sidebar docks (drawer below) and can collapse to 62px |
| `xl` | 1280px | 4 KPI cards in one row (Figma) |

`lib/use-media-query.ts` exists only for behaviour that CSS can't express (sidebar mode, calendar month count); layout always uses CSS breakpoints.

Touch rules: inputs are 16px on phones (stops iOS zoom-on-focus); hover styles only under `(hover: hover)`; the chart uses `touch-action: pan-y` so a horizontal drag scrubs and a vertical one scrolls; the scroll area uses `overscroll-behavior: contain` and a stable scrollbar gutter.

Chart internals: Y-axis column 48px + 16px gap → plot 1036 × 246 (inside 8px vertical padding = 262 row) → 8px gap → 17px X-axis.

Table columns: Date 150 · Transaction 220 · Category / Payment / Amount share the rest. Header row 46, body rows 45 (last 44).

## 9. Motion

Based on Emil Kowalski's design-engineering rules.

### 9.1 Tokens

| Token | Value | Use |
| --- | --- | --- |
| `--ease-out` (`ease-out-strong`) | `cubic-bezier(0.23, 1, 0.32, 1)` | Default for everything entering or responding |
| `--ease-in-out` (`ease-in-out-strong`) | `cubic-bezier(0.77, 0, 0.175, 1)` | On-screen movement between two states |
| `--ease-drawer` | `cubic-bezier(0.32, 0.72, 0, 1)` | Drawers / sheets (reserved) |
| `--duration-press` | 120ms | Button/row colour feedback |
| `--duration-fast` | 150ms | Popovers, label fades |
| `--duration-base` | 200ms | Toggle thumb, group expand, chevrons |
| `--duration-slow` | 250ms | Sidebar width, page-load entrance |

`ease-in` is never used for UI. Nothing exceeds 250ms.

### 9.2 Decisions

| Interaction | Frequency | Animation |
| --- | --- | --- |
| Button press | very high | **Colour + shadow only, 120ms. No scale, no translate — buttons don't bounce.** |
| Nav / row hover | very high | Background colour, 120ms, only on `(hover: hover)` devices |
| Chart scrub (crosshair, points, tooltip) | very high | **None** — follows the pointer instantly |
| Keyboard actions (⌘B, `/`, arrows on chart) | very high | **None** — ⌘B collapses the sidebar with the transition disabled |
| Tooltips | high | 400ms initial delay, then neighbours open instantly; fade + 95% scale from the trigger (`transform-origin: var(--transform-origin)`) |
| Popovers / menus | medium | 150ms fade + zoom-from-95%, origin-aware |
| Sidebar collapse (mouse) | low | Width 250ms `ease-out-strong`; labels fade 150ms |
| Planning group | low | `grid-template-rows 0fr→1fr` + opacity, 200ms — interruptible CSS transition |
| Page load | once | Cards fade up 4px, 250ms, staggered 40ms |

### 9.3 Rules

- Animate `transform` and `opacity` (and colours). The sidebar width is the single layout animation, used because it's infrequent.
- Prefer CSS transitions over keyframes for anything that can be re-triggered (they retarget mid-flight).
- Never animate from `scale(0)`; start ≥ 0.95 with opacity.
- `prefers-reduced-motion: reduce` collapses all transitions/animations to ~0ms.

### Range calendar — `components/ui/range-calendar.tsx`
Built on react-day-picker, but selection is Statsnap's own:

- **Fixed 36px cells** (`border-separate`, no flex-fraction widths), so every row is the same height.
- **Drag to select**: press a day and drag. **Either end of an existing range is a handle**: press the start or end (solid blue, with a grip tick) and drag; crossing the other end swaps them.
- **Click-click** still works: first click sets the start, the band previews on hover (lighter tint), the second click sets the end.
- Keyboard: arrows move focus (react-day-picker), Enter/Space selects.
- Band: `--accent-soft` behind the cells, half-cell caps at the endpoints, drawn as one shape: only its outer corners are rounded (a corner rounds when there is no selected day beside it and none above/below it), so stacked week rows join with straight edges instead of notches. Endpoints: `bg-accent-solid`, white text, radius 8.
- No animation while dragging (direct manipulation); only hover colours fade (120ms).

## 14. Accessibility

- Semantic landmarks: `aside` (Sidebar), `nav` (Main), `main`, `header`, `section`s labelled by their titles.
- Active page uses `aria-current="page"`; disclosure buttons expose `aria-expanded`.
- Every icon-only button has an `aria-label` and a tooltip.
- Keyboard: everything is reachable by Tab; `/` focuses search; ⌘B toggles the sidebar; chart supports ←/→ (Shift = week), Home and End; Esc clears search and closes popovers.
- Visible focus ring (`--ring-focus`) on `:focus-visible` only.
- Chart has `role="group"` + `aria-roledescription="chart"`, a descriptive label, and a live readout.
- Contrast: body text ≥ 4.5:1; `fg-subtle` limited to non-essential labels.
- Hover-only effects are gated with `(hover: hover)`; reduced motion respected.

## 15. Usage rules

**Do**
- Use semantic utilities: `bg-surface`, `text-fg-muted`, `shadow-card`, `rounded-card`.
- Use `<Icon name>` for any single-colour icon so it themes.
- Draw outlines with rings (`shadow-*`) or inset shadows to keep Figma box sizes.
- Use `tabular-nums` for figures; true minus `−` for negative money.
- Keep controls at 30px (26px inside cards).

**Don't**
- Don't hard-code hex values in components.
- Don't add scale/translate press effects to buttons.
- Don't animate keyboard-initiated actions or the chart crosshair.
- Don't use `ease-in`, `transition: all`, or durations above 250ms.
- Don't edit files in `public/figma/`.
- Don't invent new type sizes — the five steps above are the whole scale.
